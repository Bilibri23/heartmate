# Admin Runbook: Support Triage

Admins triage support by identifying the affected account, feature area, visible error, recent user action, and whether the issue is isolated or platform-wide. Start with the user's reported screen and timestamp.

For account issues, check user status and recent activity without exposing unnecessary private data. For listing, application, lease, payment, messaging, or notification issues, check the relevant queue or record before giving a user-facing answer.

If the issue involves repeated 500 or 503 responses, database errors, missing tables, deployment failures, or unavailable services, escalate to incident triage and preserve the exact error message.
